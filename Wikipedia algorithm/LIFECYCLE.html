thejesuswebsite · Wikipedia algorithm

Pipeline lifecycle and key moments

This page shows how the Wikipedia algorithm pipeline moves an article from a raw candidate to a scored, ranked entry on the site. It also lists the key moments in the pipeline's history, and the open problems still tracked in setup/issues.md.

1Lifecycle stages

Nine stages carry an article from discovery to a live entry on frontend/debate/wikipedia.html.

1
Discovery

Candidate pool

  • A headless browser crawls Category:Jesus, Category:Gospels, and linked place pages, one to two hops deep.
  • No judgment happens at this stage. Every link goes into the pool.
  • Output: candidate-pool.tsv (513 cached links).
2
Judgment

Selection

  • An agent checks each candidate against an inclusion/exclusion table.
  • Apocryphal gospels, doctrine pages, and pop-culture pages are out.
  • Miracles, parables, and lesser-known Passion events are in.
  • Permanent bans go into excluded-titles.txt (37 titles).
3
Human gate

Luke review gate

  • The selected candidates go to Luke in chat before anything is written.
  • Luke can remove titles, or ask for more rounds of selection.
  • This gate is mandatory. If Luke is unreachable, the pipeline stops.
  • Defined in skill.md, step 3b.
4
Extraction

Harvest

  • A headless browser and scripts/extract.js read the live page for each article.
  • This step produces the raw signals: verse counts, keyword hits, and category flags.
5
Offline, dev machine only

Classify

  • The classifier/ module (a MiniLM model plus FAISS search) sorts each paragraph into a bucket: data, close analysis, interpretation, or register.
  • Output: bucket-labels.json.
  • The families/ module scores each article across nine signal families into vector-family-scores.json.
  • A separate pipeline uses an LLM (DeepSeek) to label the same corpus into labels-corpus.json.
6
Ranking

Score

  • rank_engine.py merges the harvested signals with the classified ones.
  • It sums 25 weighted signals into one net_score per article.
  • It sorts every article by net_score and writes scoring-export.json, two CSV files, and wiki-bulk-paste.txt.
7
Quality gate

Calibration and validation

  • calibrate.py tests different thresholds against the frozen gold-set CSV files.
  • A gold-set label never changes to match a store's output. Only the store's threshold moves.
  • The target bar is 0.85 tier accuracy (see VALIDATION_REPORT.md, section 11.2).
  • Results are logged in CLASSIFIER_DIAGNOSIS.md and VALIDATION_REPORT.md.
8
Only step that touches the VPS

Deploy

  • git push triggers deploy.sh on the VPS.
  • deploy.sh runs import-wikipedia-scoring.js --publish --purge-missing.
  • The importer checks that all 255 × 25 signal values sum to net_score, in one transaction, before it writes anything.
  • CAUTION: the deploy path is scoring-export.json. It is never wiki-bulk-paste.txt — see key moment 4 below.
  • The result renders as a 5×5 grid on frontend/debate/wikipedia.html.
9
Standing loop

Operate

  • The !TheJesusWebsite-Wikipedia skill is the entry point: check, add, exclude, rescore.
  • The article list is fixed. A check run never adds or removes articles on its own.
  • Every outcome is logged to setup/issues.md.

2Key moments

Nine turning points in the pipeline's history, in date order where a date is known.

2026-07-28

Gold-set pilot frozen

Fourteen agents label 40 articles from real, fetched Wikipedia text. This locks in the ground truth that every later classifier is measured against.

Baseline

First classifier scores 0.303 tier accuracyFailed

The original three-store classifier cannot tell close analysis apart from interpretation. Tier 1 and tier 2 content collapse into each other.

2026-07-30

Architecture fix raises accuracy to 0.667Still below gate

A fourth "close-analysis" store is added, and a bug is fixed: the register gate had silently used the data store's threshold instead of its own. Accuracy improves but stays under the 0.85 gate.

2026-07-30

Production incidentData loss

Someone deletes every row in the wikipedia_articles table and pastes wiki-bulk-paste.txt, believing it is the deploy step. Every score is lost. A manual database migration restores it. skill.md now carries a standing warning about this exact mistake.

2026-07-31

LLM labels become the primary sourcePromoted

Row 3 (the dominant scoring signal) goes live. A DeepSeek-based labelling pipeline reaches 0.926 agreement with human labels, and becomes the primary source. The embedding classifier (0.641–0.667 accuracy) becomes a secondary check — tracked as issue #163.

2026-07-31

First vector family goes liveActivated

Row 10, literary analysis, is the first of nine vector families to clear its 0.80 precision floor. It fires on about 19% of the corpus.

2026-08-28

Documents disagree on what shipsNeeds a check

VALIDATION_REPORT.md still states that row 3 ships from the classifier's own tier score (0.667), not the LLM label. This does not match the record of key moment 5, and the two documents need reconciling.

Issue #231

Trained paragraph head reaches 0.776–0.788Not active

A linear probe trained on raw embeddings beats the 0.671 store-scoring baseline, but still falls short of the 0.85 gate. It is not turned on. A decision on its scope is still open.

2026-09-20

Gold-set labelling rule changesSpec update

After an issue #231 audit, content about art, film, and worship is now labelled "interpretation" regardless of its register. The rule evolves after production use finds the edge case.

3Open problems

Tracked in setup/issues.md and the guide documents, as of the last read.

#163 Classifier accuracy still fails its gate.

The classifier's own tier accuracy (0.641–0.667) stays under the 0.85 gate. ALGORITHM_GUIDE_the_what.md and ALGORITHM_GUIDE_the_how.md call this resolved by the LLM-label switch, but VALIDATION_REPORT.md and OPERATOR_GUIDE.md still describe the classifier as what ships. These documents need to agree.

#161 Five keyword fallbacks are broken.

Marked pending in PENDING_SIGNAL_KEYS. A grey cell on one of these signals in the scoring grid is expected, not a new bug.

no number Eight of nine vector families run on their fallback, not their score.

Only literary analysis (row 10) clears its precision floor. The other eight sit at precision 0.0 in rank_engine.py and fire from their dormant keyword fallback instead.

#231 Parable and teaching exception is unsettled.

Whether a parable or a teaching passage should follow the new "reception is interpretation" rule is still an open question. The trained paragraph head from this same issue is not active.
