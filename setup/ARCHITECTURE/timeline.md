# Timeline

Events from the life of Jesus appear in order, so a reader sees what happened when. An admin sets each event's period and exact spot. Shared placement rules draw it identically in the editor and on the public page.

## Shape

- **Canonical:** `cluster-logic/` holds density, placement, labels, label collision, label layout, offsets and zoom stacks. `timeline-era-heading-placement.js` holds the era band layout. The public `timeline-render.js` imports them. The admin pages load classic scripts, so `timeline-bridge.js` publishes them as `window.Admin*` globals and must load before the admin timeline scripts (`admin/diagrams/timeline.html`). `cluster-map-pins.js` (maps, `maps.md`) imports `cluster-labels.js`, which imports `cluster-density.js`: a change to either moves the map pin labels too.
- **Offset maths:** `timeline-offsets.js` holds the pixel conversion, the `top` percentage mapping and its inverse, the vertical (mobile) mapping, and the clamp limits for a stored node offset, among them `DRAG_LIMIT_X`. The bridge publishes all of it except the vertical mapping, which only the public page uses. `timeline-node-bounds.js` takes its clamps from the same bridge.
- **Copies kept by hand:** classic admin scripts cannot import the public modules, so the admin `timeline-geometry.js` (scales, periods, eras) and `timeline-transform.js` (pan maths) mirror their public namesakes. Rows 2 and 9 guard the geometry and the periods. Nothing guards the era boundaries (`ERA_BOUNDARIES` in `timeline-data.js`, `ERA_STARTS` in the admin geometry) or the pan maths: change both sides together. The admin zoom delegates to `admin-canvas-zoom.js`.
- **Zoom scale:** both zoom modules (`timeline/timeline-zoom.js` and the admin `timeline-zoom.js`) publish the live scale as `--timeline-zoom-scale` on the world element. The stylesheets divide line widths, stack buttons and era headings by it. Renaming it in one place makes lines and buttons grow with the zoom. The public vertical layout has no zoom, so the property is unset there and the stylesheets fall back to 1.
- **Era class:** the public `timeline-render.js` derives `era--<kebab>` from the era key. The admin timeline and maps editors share one conversion, `AdminEraUtils.eraToKebab` (row 12). The era colour comes from the stylesheets with a matching `era--<kebab>` selector, and from the same class on the chips in `frontend/evidence/timeline/`. The admin `timeline-era-filter.js` finds dots by that class.
- **Mobile layout:** under the breakpoint of row 8 the public page builds a vertical layout with no zoom and no stacks, and `computeEraHeadingPositions` places the headings in the world. The admin editor has only the horizontal layout.
- **Era heading band:** on the horizontal layout the headings sit in a band at the top of the canvas, outside the zoomed world. `computeEraBandLayout` assigns lanes. The public `renderEraBand` and the admin `Events.renderEraBand` build the band, and each keeps it in step with pan and zoom through its zoom module's `onTransformChange`.
- **Zoom stacks (public only):** zoomed out, nearby nodes gather in a column with a count button (`.timeline-stack`). Between `STACK_BLEND_START` and `STACK_BLEND_END` each node moves from its stack spot to its exact spot. `computeZoomStacks` works in world pixels; `applyZoomStacks` in `timeline-render.js` moves the dots and places the labels again after each zoom. A stack button zooms to its events (`fitStackView`, called from `timeline-interactions.js`).
- **Label layout:** `layoutLabelsBesideNodes` works in pixels of the dot field (`TIMELINE_CANVAS_HEIGHT_PX` tall), and every dot is an obstacle. The public `layoutHorizontalLabels` and the admin `Events.relayoutLabels` measure the labels and apply the result. The vertical layout uses `cluster-label-collision.js`, which also serves the mobile era headings.
- **Tooltip:** the public dot tooltip answers a real mouse only (`isMousePointer` in `timeline-input-guards.js`). A tap opens the detail panel and shows no tooltip. `timeline-interactions.js` wires the page on load, so the pure key and pointer tests live in `timeline-input-guards.js` for tests to import.
- **Admin drag:** `timeline-node-drag.js` keeps the dot under the pointer by dividing pointer distances by the zoom scale and converting them with `window.AdminTimelineOffsets`. While a node moves it calls `Events.relayoutLabels`. A drop stages the offsets in `timeline-staged-changes.js`. At the end of a drag it sets `_timelineDragActive` on the dot, and the dot's click handler in `timeline-events.js` reads and clears it so the click that ends a drag does not select the event. Renaming it in one file makes every drop open the edit panel.
- **Save path:** the admin save button calls `timeline-staged-changes.js`, which calls `UpdateRecord.saveEvent` (`update-record.js`), which sends `PUT /evidence/:id`. `validateOffsets` in `evidence.model.js` clamps the offsets there (row 2).
- **API:** `api/server.js` mounts `api/routes/timeline.js` at `/timeline`. `GET /timeline` returns published events only, narrowed by `timeline_era`. `GET /timeline/admin` is behind `requireAuth` and adds drafts, or the unplaced events with `?unplaced=1`. `GET /timeline/:era` returns one published era. The consumers are `frontend/assets/js/api.js` (through `timeline-data.js`), the admin `timeline-events.js` and the MCP tool `getTimelineEvents.js`, which keeps its own era list.
- **Era pages:** the pages under `frontend/evidence/timeline/` are static, git-tracked HTML. `api/scripts/embed-initial-data.js` writes a `timeline-data` snapshot into each at deploy (`npm run embed-data` in `deploy.sh`; the mechanism is in `publishing-pipeline.md`, the deploy order in `deployment.md`). `timeline-interactions.js` paints the snapshot, then re-renders only if the live fetch differs (row 6).

## Extending it

- **Tuning behaviour** (spacing, thresholds, tier boundaries): edit the canonical module. Then check rows 1 and 2.
- **A new field that the renderer reads:** add it to the snapshot `SELECT` as well (row 6).
- **A new period or era:** change each place below, in this order.
  1. `database/schema.sql`: the `timeline_era` and `timeline_period` CHECK lists, with a migration.
  2. `api/models/timeline.model.js`: `ERA_ORDER` and `PERIOD_ORDER`.
  3. `frontend/assets/js/timeline/timeline-data.js`: `TIMELINE_PERIODS`, `ERA_LABELS` and `ERA_BOUNDARIES`.
  4. `admin/assets/js/admin-timeline/timeline-geometry.js`: `TIMELINE_PERIODS`, `ERA_ORDER`, `ERA_LABELS` and `ERA_STARTS`. Also `admin/assets/js/admin-timeline-taxonomy.js` (`ERAS`, `PERIODS_BY_ERA`).
  5. `mcp-server/tools/getTimelineEvents.js`: the era list in the description, the schema and the handler.
  6. A new era only: the `--era-*` token in `frontend/assets/css/base/variables.css` and `admin/assets/css/admin-base/variables.css`; every stylesheet with an `era--<kebab>` rule (search for `era--`); a chip in `frontend/evidence/timeline/index.html`; a new page in `frontend/evidence/timeline/` and its entry in the era page list of `api/scripts/embed-initial-data.js`.
  7. Run `api/tests/guide-timeline.test.js` (rows 8 and 9).

## Not documented here

Spacing values per density tier, the collision tier count and the stack thresholds are in the canonical modules. They change most often.
