# Timeline

Evidence is placed in order across the life of Jesus, so a reader sees what happened when. An admin sets each event's period and exact spot. The editor and the public page then draw the same layout.

**Source of truth:** `frontend/assets/js/cluster-logic/` and `frontend/assets/js/timeline/` — win any disagreement with this doc.
**Spans:** `frontend/assets/js/cluster-logic/cluster-density.js`, `frontend/assets/js/cluster-logic/cluster-placement.js`, `frontend/assets/js/cluster-logic/cluster-labels.js`, `frontend/assets/js/cluster-logic/cluster-label-layout.js`, `frontend/assets/js/cluster-logic/cluster-label-collision.js`, `frontend/assets/js/cluster-logic/timeline-offsets.js`, `frontend/assets/js/cluster-logic/timeline-zoom-stacks.js`, `frontend/assets/js/timeline/timeline-era-heading-placement.js`, `frontend/assets/js/timeline/timeline-render.js`, `frontend/assets/js/timeline/timeline-geometry.js`, `frontend/assets/js/timeline/timeline-data.js`, `admin/assets/js/admin-timeline/timeline-events.js`, `admin/assets/js/admin-timeline/timeline-node-drag.js`, `admin/assets/js/admin-timeline/timeline-node-bounds.js`, `admin/assets/js/admin-timeline/timeline-staged-changes.js`, `admin/assets/js/admin-timeline/timeline-axis.js`, `admin/assets/js/admin-timeline/timeline-geometry.js`, `admin/assets/css/admin-diagrams/timeline-canvas.css`, `admin/diagrams/timeline.html`, `api/scripts/embed-initial-data.js`, `api/models/evidence.model.js`.

## Shape

- **Canonical:** `frontend/assets/js/cluster-logic/` holds density, placement, labels, label collision, label layout, offsets and zoom stacks for the timeline. Era-heading placement is canonical in `frontend/assets/js/timeline/timeline-era-heading-placement.js`. The public `timeline-render.js` imports them directly. The admin editor reads them through `window.Admin*` bridges.
- **Offset maths:** `cluster-logic/timeline-offsets.js` holds the pixel conversion, the `top` percentage mapping and the clamp limits for a stored node offset. The admin editor reads it through `timeline-offsets-bridge.js`. `timeline-node-bounds.js` takes its clamps from the same bridge.
- **Era heading band:** on the horizontal layout the headings sit in a band at the top of the canvas, outside the zoomed world. `computeEraBandLayout` (in `timeline-era-heading-placement.js`) assigns lanes from measured heading widths and the zoom. The public `timeline-render.js` (`renderEraBand`) and the admin `timeline-events.js` (`Events.renderEraBand`) build the band, and each keeps it in step with pan and zoom through its zoom module's `onTransformChange`. The vertical (mobile) layout keeps headings in the world and uses `computeEraHeadingPositions`.
- **Zoom stacks (public only):** zoomed out, nodes within `STACK_MERGE_PX` on screen gather in a column at their mean position, with a count button (`.timeline-stack`) over the column. From the zoom `STACK_BLEND_END` (the default zoom, 1) every node sits at its exact stored position; between `STACK_BLEND_START` and `STACK_BLEND_END` each node moves from its stack spot to its exact spot. `computeZoomStacks` works in world pixels; `timeline-render.js` (`applyZoomStacks`) moves the dots, builds the buttons and places the labels again after each zoom. A stack button zooms to its events (`fitStackView`, `timeline-interactions.js`). The vertical (mobile) layout has no zoom and no stacks.
- **Admin drag:** `timeline-node-drag.js` keeps the dot under the pointer: it divides pointer distances by the zoom scale and converts them with `window.AdminTimelineOffsets`. While a node moves it calls `Events.relayoutLabels`, which places every label again, so titles move out of each other's way and keep their leader lines. A drag stops at `DRAG_LIMIT_X` of the slot (`timeline-node-bounds.js`); a node that was saved further out keeps its own start as the limit, so grabbing it does not pull it back. A drop stages the offsets in `timeline-staged-changes.js`. The save button shows the count and is enabled only while a change is staged.
- **Label layout:** on the horizontal layout each title starts just right of its dot, then tries the left side, then moves up or down in steps and gets a leader line from the start of its name to the dot. Every dot is an obstacle. `layoutLabelsBesideNodes` works in pixels of the dot field (`TIMELINE_CANVAS_HEIGHT_PX` tall). The public `timeline-render.js` (`layoutHorizontalLabels`) and the admin `timeline-events.js` (`Events.relayoutLabels`) measure the labels and apply the result. The vertical (mobile) layout keeps `cluster-label-collision.js`, which also serves the mobile era headings.
- **Plain object and `Map`:** `computeDotPositions` takes and returns a `Map` (period to events). `timeline-events.js` builds and reads a `Map`.

## Extending it

- **Tuning behaviour** (spacing, thresholds, tier boundaries): edit the canonical module. Then check rows 1 and 2.
- **A new field that the renderer reads:** add it to the snapshot `SELECT` as well (row 6).
- **A new period or era:** the allowed values live in `database/schema.sql`. Change the schema first, then the period list in `frontend/assets/js/timeline/timeline-data.js` and in the admin `timeline-geometry.js`.

## Not documented here

Spacing values per density tier, the collision tier count and the stack thresholds are in the canonical modules. They change most often.
